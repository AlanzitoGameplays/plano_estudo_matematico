# ESTRUTURAS CANÔNICAS DO PLANO DE ESTUDO MATEMÁTICO

## Versão 1.1 — 2026

**Estado:** definitiva e congelada  
**Abrangência:** Estrutura Única do Tópico; Estrutura do Bloco — Núcleo Matemático Comum; Estrutura do Bloco — Texto Teórico; Estrutura do Bloco — Texto Prático; Estrutura das Partes em Tópicos sem Blocos — Núcleo Matemático Comum; Estrutura das Partes em Tópicos sem Blocos — Texto Teórico; Estrutura das Partes em Tópicos sem Blocos — Texto Prático.

---

# Função do documento

As Estruturas Canônicas do Plano de Estudo Matemático constituem um **instrumento de decisão anterior à produção**.

Sua função é orientar a arquitetura de Tópicos, Blocos e Partes antes da redação do Texto Teórico e antes da construção do Texto Prático, permitindo decidir com suficiente clareza:

- o que está sendo ensinado;
- por que precisa ser ensinado;
- de que conhecimentos depende;
- em que ordem deve aparecer;
- com que profundidade;
- sob qual estatuto matemático;
- por quais representações;
- com quais fontes;
- que capacidades a teoria precisa construir;
- que competências a prática poderá tornar observáveis;
- onde o conteúdo deve terminar;
- qual unidade de produção é adequada.

As Estruturas Canônicas **não são um formulário rígido**, uma sequência obrigatória de etapas nem um artefato que precise gerar automaticamente um arquivo de “estrutura definitiva” para cada Tópico.

As decisões podem ser realizadas, auditadas e congeladas diretamente durante o planejamento.

A estrutura existe para melhorar as decisões que antecedem a produção, não para competir com o próprio conteúdo.

---

# Relação com os demais documentos do Plano

As Estruturas Canônicas possuem função diferente das Regras Gerais do Texto Teórico e das Regras Gerais do Texto Prático.

As Estruturas Canônicas perguntam:

> **o que precisa ser construído, de que depende, até onde deve avançar e como deve ser arquitetado?**

As Regras Gerais perguntam:

> **como uma arquitetura já decidida deve ser transformada em texto, atividades, exemplos, exercícios, gabaritos e recursos?**

O fluxo funcional é:

\[
\boxed{
\text{Macroestrutura Curricular}
\rightarrow
\text{Estruturas Canônicas}
\rightarrow
\text{Decisões Arquitetônicas}
\rightarrow
\text{Prompt-Mestre, quando útil}
\rightarrow
\text{Produção}
}
\]

O Prompt-Mestre não constitui uma nova Estrutura Canônica. Ele é um **resumo operacional das decisões já tomadas** quando uma mesma arquitetura precisa governar várias unidades de produção.

Como Texto Teórico e Texto Prático pertencem a projetos diferentes, cada projeto pode possuir seu próprio Prompt-Mestre do Tópico.

Não criar automaticamente um Prompt-Mestre para cada Bloco.

---

# Princípio geral

O princípio superior deste documento é:

\[
\boxed{
\text{a estrutura deve ser suficiente para controlar o raciocínio
e simples o bastante para não competir com o conteúdo}
}
\]

Também se preservam três regras fundamentais:

\[
\boxed{
\text{a arquitetura deve seguir a dependência matemática,
não a tradição editorial das fontes}
}
\]

\[
\boxed{
\text{a tecnologia deve servir à arquitetura;
a arquitetura não deve nascer da tecnologia}
}
\]

\[
\boxed{
\text{completude curricular}
\neq
\text{cobertura enciclopédica}
}
\]

---

# Como utilizar as Estruturas Canônicas

As perguntas deste documento são **perguntas de decisão**, não campos obrigatórios de formulário.

Uma pergunta pode:

- exigir desenvolvimento extenso;
- ser respondida em poucas linhas;
- ser resolvida implicitamente por outra decisão;
- não se aplicar à unidade analisada.

Não é necessário reproduzir todas as perguntas na resposta de planejamento.

O objetivo é que, ao final da estruturação, as decisões realmente importantes estejam suficientemente claras.

Aplicar sempre a regra:

> **usar apenas a quantidade de estrutura necessária para orientar com segurança a produção.**

# Ontologia curricular

## Tópico

Um **Tópico** é uma unidade curricular com identidade matemática própria o bastante para possuir:

- objeto, relação, operação, estrutura ou problema central;
- pergunta superior;
- função curricular;
- contrato de entrada;
- contrato de saída;
- fronteiras;
- movimento matemático identificável.

O Tópico pode ser organizado:

\[
\text{Tópico}\rightarrow\text{Blocos}\rightarrow\text{Partes}
\]

ou diretamente:

\[
\text{Tópico}\rightarrow\text{Partes}.
\]

## Bloco

Um **Bloco** é uma unidade intermediária dentro do Tópico.

Só se justifica quando possui suficientemente:

\[
\boxed{
\text{identidade própria}
+
\text{pergunta local}
+
\text{movimento próprio}
+
\text{contrato de saída}
+
\text{autonomia funcional}
}
\]

Não criar Blocos para:

- equilibrar páginas;
- imitar capítulos de livros;
- produzir simetria;
- separar artificialmente conteúdos que pertencem ao mesmo movimento.

## Parte

Uma **Parte** é uma unidade de construção matemática correspondente a uma mudança perceptível de:

- objeto;
- relação;
- operação;
- representação;
- dificuldade;
- formalização;
- função;
- estratégia;
- método de justificativa ou demonstração.

Partes não precisam ter extensão semelhante.

## Seção

Uma **Seção** é uma divisão editorial interna de uma Parte.

Não constitui nova Estrutura Canônica.

Criá-la apenas quando existir mudança real de raciocínio.

# Princípios canônicos comuns

## 1. Identidade antes da enumeração

Uma unidade curricular não deve nascer apenas de uma lista de assuntos.

Antes de perguntar “o que entra?”, perguntar:

> **que objeto, relação, problema ou transformação mantém esta unidade matematicamente coesa?**

---

## 2. Dependências explícitas

Todo conceito, símbolo, procedimento, representação, demonstração ou exercício deve aparecer apenas depois das condições matemáticas de que realmente depende.

Não admitir pré-requisito oculto.

---

## 3. Contratos de entrada e saída

Toda unidade relevante deve possuir:

### Contrato de entrada

O que já pode ser legitimamente utilizado sem reensino.

### Contrato de saída

O novo estado de compreensão ou competência que deve existir ao final.

---

## 4. Fronteiras positivas

Quando útil, classificar conteúdos em:

- **entra e será ensinado;**
- **já existe e será utilizado;**
- **será retomado brevemente;**
- **será apenas preparado;**
- **será deliberadamente adiado;**
- **fica fora do escopo.**

Fronteiras existem para proteger a coerência curricular, não para impedir conexões.

---

## 5. Necessidade matemática

Um conceito importante deve, sempre que possível, entrar porque resolve uma insuficiência real.

Evitar tanto:

- definições soltas sem função;
- teatralização artificial de conceitos simples.

---

## 6. Continuidade sem reensino automático

Um conhecimento já construído deve reaparecer realizando trabalho novo.

Preservar:

\[
\boxed{
\text{construído}
\rightarrow
\text{estabilizado}
\rightarrow
\text{utilizado}
\rightarrow
\text{transferido}
}
\]

Retomar não significa recomeçar.

---

## 7. Profundidade proporcional

A profundidade deve responder a:

- importância estrutural;
- recorrência;
- dificuldade conceitual;
- dificuldade operacional;
- potencial de transferência;
- risco de compreensão superficial;
- relevância demonstrativa;
- relevância avaliativa.

Não distribuir espaço por simetria.

---

## 8. Assimetria legítima

Tópicos, Blocos, Partes, exemplos, demonstrações e exercícios podem ter extensões muito diferentes.

A assimetria é legítima quando decorre da matemática.

---

## 9. Estatuto matemático explícito

Quando pertinente, distinguir:

- noção de trabalho;
- definição;
- convenção;
- propriedade;
- identidade;
- consequência;
- regra;
- procedimento;
- algoritmo;
- teorema;
- método de demonstração.

Não tratar resultados de estatutos diferentes como se fossem equivalentes.

---

## 10. Formalização proporcional

Formalizar quando a formalização:

- aumenta precisão;
- explicita dependências;
- permite demonstração;
- prepara conteúdos posteriores;
- reduz ambiguidade.

Evitar formalismo cuja única função seja parecer rigoroso.

---

## 11. Notação introduzida por função

Todo símbolo deve entrar quando já houver significado suficiente para utilizá-lo.

Evitar:

- excesso de variantes concorrentes;
- notação antecipada;
- símbolos que serão usados apenas uma vez sem ganho real.

---

## 12. Demonstração proporcional

Nem toda verdade precisa receber prova formal.

Perguntar:

- a demonstração ensina um método?;
- mostra por que o resultado é verdadeiro?;
- desenvolve linguagem matemática?;
- prepara raciocínio futuro?;
- acrescenta compreensão além da afirmação?

Se não, uma justificativa mais econômica pode ser superior.

---

## 13. Exemplos auditados por custo curricular

Todo exemplo possui custo.

Perguntar:

- que pré-requisitos exige?;
- que variáveis introduz?;
- que confusões pode gerar?;
- que trabalho novo realiza?;
- pode ser compreendido sem desviar o foco?

Exemplo famoso não é automaticamente exemplo adequado.

---

## 14. Fontes subordinadas à arquitetura

Preservar:

\[
\boxed{\text{FONTE}\rightarrow\text{FUNÇÃO}}
\]

Rejeitar:

\[
\boxed{\text{FONTE}\rightarrow\text{ARQUITETURA AUTOMÁTICA}}
\]

Um livro pode ser rigoroso e ainda assim possuir:

- sequência inadequada ao Plano;
- formalismo excessivo;
- cobertura enciclopédica;
- terminologia que não será adotada;
- exemplos com custo curricular alto.

---

## 15. Avaliações calibram, não governam

Vestibulares, ENEM, FATEC, concursos e olimpíadas podem ajudar a calibrar:

- autonomia;
- formas de cobrança;
- integração;
- dificuldade;
- linguagem;
- distratores;
- tempo de resolução.

Não devem determinar sozinhos a arquitetura do currículo.

---

## 16. Teoria e prática conectadas, mas estruturalmente distintas

A teoria estabelece o espaço legítimo da prática.

A prática possui autonomia didática própria.

A prática não precisa reproduzir:

- Blocos;
- Partes;
- seções;
- exemplos;
- ordem expositiva da teoria.

Ela pode reorganizar conhecimentos já construídos para desenvolver:

- fluência;
- integração;
- autonomia;
- transferência.

---

## 17. Unidade de produção determinada pela densidade

Não estabelecer previamente:

- Bloco inteiro;
- Parte por Parte;
- várias etapas fixas.

Aplicar:

> **pedir apenas a quantidade de texto ou prática que pode receber o aprofundamento que merece.**

---

## 18. Congelamento encerra refinamento opcional

Uma arquitetura deve ser congelada quando estiver suficientemente resolvida.

Não continuar refinando apenas porque outra organização também seria possível.

Reabrir apenas diante de problema real.

---

# Regimes matemáticos

Os cinco regimes a seguir constituem eixos transversais. Nem todos precisam ter a mesma intensidade.

## A. Regime conceitual

Pergunta:

> **que objetos, relações, propriedades, operações, estruturas e distinções estão sendo construídos?**

Determinar:

- conceitos nucleares;
- conceitos auxiliares;
- estatutos;
- relações de dependência;
- necessidade de definição;
- necessidade de generalização.

---

## B. Regime simbólico-notacional

Perguntar:

- que símbolos entram?;
- quando entram?;
- que função realizam?;
- que variantes precisam ser evitadas?;
- que variantes apenas precisam ser reconhecidas?;
- que ambiguidades devem ser controladas?

A notação deve reduzir carga cognitiva depois que seu significado está disponível.

---

## C. Regime operacional

Perguntar:

- que manipulações precisam ser compreendidas?;
- que procedimentos precisam ser executados?;
- que procedimentos exigem fluência?;
- o que é ferramenta auxiliar?;
- o que é objeto central?

Uma progressão possível, quando pertinente:

\[
\text{compreensão}
\rightarrow
\text{execução com apoio}
\rightarrow
\text{execução autônoma}
\rightarrow
\text{fluência}
\]

---

## D. Regime demonstrativo

Decidir o grau necessário de:

- explicação;
- verificação;
- justificativa;
- contraexemplo;
- argumento;
- demonstração.

Perguntar também:

- que linguagem demonstrativa já está disponível?;
- que método de demonstração pode ser legitimamente utilizado?;
- que demonstrações possuem função formativa?

---

## E. Regime representacional

Perguntar:

> **o que precisa tornar-se perceptível além da prosa e da simbolização?**

Pode envolver:

- estrutura;
- relação;
- transformação;
- posição;
- comportamento;
- variação;
- decomposição;
- correspondência;
- organização de dados;
- configuração geométrica.

---

# Prosa matemática

A prosa constitui uma dimensão arquitetônica do Texto Teórico.

No nível do Tópico, definir apenas o perfil geral.

No nível do Bloco ou Parte, decidir de forma concreta como ela avança.

Podem aparecer, conforme necessidade:

- prosa conceitual-explicativa;
- simbólico-explicativa;
- operacional;
- demonstrativa;
- comparativa;
- quantitativa;
- geométrico-descritiva;
- investigativa;
- combinações assimétricas.

Perguntar:

- qual será o ponto de partida?;
- qual insuficiência ou problema precisa aparecer?;
- quando a definição entra?;
- quando a simbolização entra?;
- como exemplos se integram?;
- onde a prosa deve desacelerar?;
- onde deve ser econômica?;
- como fórmulas e texto dividem trabalho?;
- onde uma demonstração deve interromper a exposição?;
- como as transições serão construídas?

Não transformar nenhum regime de prosa em modelo universal.

---

# Corpus

## Corpus teórico

No projeto matemático, o corpus teórico é principalmente o **conjunto de fontes bibliográficas e matemáticas utilizadas para sustentar, verificar e enriquecer a produção**.

As fontes podem cumprir funções distintas:

- precisão;
- terminologia;
- pedagogia;
- demonstração;
- exemplos;
- representações;
- história conceitual, quando pertinente;
- controle de fronteira.

## Corpus prático

O corpus prático pode incluir:

- exercícios de livros;
- provas oficiais;
- vestibulares;
- ENEM;
- FATEC;
- concursos;
- olimpíadas;
- bancos de questões;
- questões adaptadas;
- questões autorais.

Seu papel é calibrar e alimentar a prática, não governar o currículo.

# Princípio representacional do Plano Matemático

Aplicar:

\[
\boxed{
\text{FUNÇÃO MATEMÁTICA}
\rightarrow
\text{REPRESENTAÇÃO}
\rightarrow
\text{FIDELIDADE}
\rightarrow
\text{IMPLEMENTAÇÃO}
}
\]

## 1. Função matemática

Perguntar:

> **o que o estudante precisa perceber, interpretar, construir ou utilizar?**

## 2. Representação

Escolher o registro que realiza melhor essa função:

- simbólico;
- numérico;
- tabular;
- gráfico;
- geométrico;
- diagramático;
- espacial;
- ilustrativo;
- híbrido.

## 3. Fidelidade

Determinar o grau de precisão necessário.

Distinguir:

- representação esquemática;
- representação matematicamente informativa.

## 4. Implementação

Somente depois decidir tecnicamente:

- SVG;
- HTML/CSS;
- raster;
- gráfico gerado;
- tabela;
- ilustração;
- imagem;
- outro recurso.

A implementação não deve criar a necessidade pedagógica.

# I. ESTRUTURA ÚNICA DO TÓPICO

## Função

Definir a **macroarquitetura matemática completa do Tópico** antes da produção do Texto Teórico e do Texto Prático.

A Estrutura do Tópico é única.

Ela organiza:

- identidade;
- pergunta central;
- função curricular;
- contratos;
- fronteiras;
- movimento global;
- dependências;
- regimes;
- organização em Blocos ou Partes;
- visão geral da teoria;
- visão geral da prática.

Ela não precisa decidir em detalhe:

- quantidade exata de exercícios;
- SVG específico;
- número fixo de exemplos;
- fonte de cada parágrafo;
- divisão obrigatória da produção.

Essas decisões pertencem ao planejamento detalhado das unidades internas.

---

## A. Identidade e posição curricular

### 1. Qual é a identidade matemática do Tópico?

Que objeto, relação, operação, estrutura, problema ou transformação realmente lhe dá unidade?

### 2. Qual é sua pergunta central?

Que pergunta intelectual deve estar suficientemente respondida ao final?

### 3. Qual insuficiência curricular torna o Tópico necessário?

O que o estudante já consegue fazer e onde esse conhecimento deixa de ser suficiente?

### 4. Qual é sua função curricular?

O Tópico:

- introduz linguagem?;
- cria infraestrutura?;
- formaliza?;
- operacionaliza?;
- integra?;
- prepara outra área?;
- fecha uma sequência?

### 5. Qual importância e profundidade merece?

Considerar:

- recorrência;
- dependências posteriores;
- dificuldade;
- transferência;
- custo de compreensão superficial;
- importância avaliativa.

---

## B. Contratos e fronteiras

### 6. Qual é o contrato de entrada?

Que conhecimentos podem ser legitimamente utilizados?

### 7. O que precisa apenas ser retomado?

Que conceitos anteriores reaparecem com função nova?

### 8. O que ainda não pode ser pressuposto?

Que conhecimentos posteriores precisam ser protegidos pela fronteira?

### 9. Qual é o contrato de saída?

Ao terminar, o estudante deverá conseguir compreender e, quando pertinente:

- definir;
- distinguir;
- representar;
- interpretar;
- operar;
- transformar;
- justificar;
- demonstrar;
- generalizar;
- transferir.

### 10. Quais são as fronteiras do Tópico?

Classificar somente quando útil:

- ensina;
- utiliza;
- retoma;
- prepara;
- adia;
- exclui.

---

## C. Movimento e dependências

### 11. Qual é o movimento conceitual global?

Construir a transformação matemática do começo ao fim.

Exemplos possíveis:

\[
\text{problema}
\rightarrow
\text{necessidade}
\rightarrow
\text{conceito}
\rightarrow
\text{uso}
\]

\[
\text{objeto}
\rightarrow
\text{relação}
\rightarrow
\text{operação}
\rightarrow
\text{estrutura}
\]

Não impor fórmula universal.

### 12. Qual é o mapa de dependências?

Que conceitos dependem de quais?

Existe:

- antecipação?;
- dependência circular?;
- pré-requisito escondido?;
- notação antes do significado?

### 13. Como o Tópico se conecta ao conhecimento anterior?

A conexão deve ser conceitual, não apenas cronológica.

### 14. O que entrega aos Tópicos posteriores?

Que linguagem, procedimento, representação ou método ficará disponível?

---

## D. Regimes gerais

### 15. Qual é o regime conceitual predominante?

### 16. Qual é o regime simbólico-notacional predominante?

### 17. Qual é o regime operacional predominante?

### 18. Qual é o regime demonstrativo predominante?

### 19. Qual é o regime representacional predominante?

Não procurar equilíbrio artificial entre eles.

---

## E. Prosa, corpus e representação em nível macro

### 20. Qual é o perfil geral da prosa?

Apenas indicar tendências.

Não escrever ainda a arquitetura de cada Parte.

### 21. Que famílias de fontes podem ser importantes para o corpus teórico?

### 22. Que famílias de fontes podem ser importantes para o corpus prático?

### 23. O que precisa tornar-se perceptível além da prosa e da simbolização?

### 24. Que necessidades representacionais gerais existem?

Não decidir prematuramente a tecnologia.

---

## F. Relação macro entre teoria e prática

### 25. Que capacidades gerais a teoria precisa construir?

### 26. Que competências gerais a prática deverá tornar observáveis?

### 27. Há conteúdos predominantemente conceituais, operacionais, demonstrativos ou representacionais que exigirão tratamentos práticos distintos?

A prática não precisa reproduzir a ordem expositiva da teoria.

---

## G. Organização interna

### 28. O Tópico precisa de Blocos?

Criar Blocos apenas diante de mudanças reais de:

- objeto;
- pergunta;
- escala;
- operação;
- dificuldade;
- representação;
- função.

### 29. Se houver Blocos, quais são necessários?

Cada Bloco deve sobreviver ao teste:

\[
\text{identidade}
+
\text{pergunta}
+
\text{movimento}
+
\text{saída}
+
\text{autonomia}
\]

### 30. Que Partes aparecem em cada Bloco em nível macro?

Não detalhar ainda sua produção.

### 31. Qual é a ordem e a dependência entre os Blocos?

### 32. Se não houver Blocos, quais Partes são necessárias?

Utilizar o menor número capaz de realizar o movimento global.

---

## H. Calibração e encerramento

### 33. Como avaliações externas calibram o Tópico?

Somente registrar o que realmente acrescentam.

### 34. Qual é o critério de encerramento?

Onde a pergunta central está suficientemente resolvida sem invadir conteúdo posterior?

---

Ao final da Estrutura do Tópico, devem estar suficientemente claros:

- identidade;

# II. ESTRUTURA DO BLOCO — NÚCLEO MATEMÁTICO COMUM

## Função

Definir aquilo que **Texto Teórico e Texto Prático compartilham matematicamente** antes de planejar suas materializações didáticas próprias.

A bifurcação ocorre somente depois que o núcleo do Bloco estiver suficientemente claro.

---

## Perguntas canônicas

### 1. Qual é a identidade matemática do Bloco?

### 2. Qual é sua pergunta central?

### 3. Que insuficiência do estado anterior o torna necessário?

### 4. Qual é sua função dentro do Tópico?

### 5. Qual profundidade merece?

### 6. Qual é seu contrato de entrada?

### 7. O que precisa apenas ser retomado?

### 8. O que ainda não pode ser pressuposto?

### 9. Qual é seu contrato de saída?

### 10. Quais são suas fronteiras?

### 11. Quais conceitos são nucleares?

### 12. Quais conceitos são auxiliares?

### 13. Existe terminologia ou formalismo dispensável?

### 14. Qual é o estatuto matemático dos conteúdos?

### 15. Qual é o movimento completo do Bloco?

### 16. Qual é seu mapa de dependências?

### 17. O que deve emergir por necessidade?

### 18. O que pode ser definido diretamente?

### 19. Onde estão os gargalos?

### 20. Quais pontos são simples e merecem tratamento econômico?

### 21. Quais confusões precisam realmente ser resolvidas?

### 22. Que notação precisa ser estabilizada?

### 23. O Bloco precisa de Partes?

### 24. Qual é o menor número de Partes necessário?

### 25. Qual é a identidade e função de cada Parte?

### 26. Que dependência existe entre elas?

### 27. Qual é o critério de encerramento do Bloco?

---

## Auditoria do núcleo

Antes da bifurcação, verificar:

- as Partes formam um movimento inteligível?;
- existe lacuna?;
- existe reensino?;
- existe antecipação?;
- alguma Parte perdeu função própria?;
- alguma deveria ser fundida ou dividida?;
- existe simetria artificial?;
- alguma notação entra cedo demais?;
- algum conteúdo depende de conhecimento indisponível?;
- o Bloco continua merecendo existir como Bloco?

# III. ESTRUTURA DO BLOCO — TEXTO TEÓRICO

## Função

Decidir **como a compreensão matemática do Bloco será construída na exposição teórica**.

O Texto Teórico não precisa descobrir sua arquitetura enquanto é escrito.

A estrutura teórica deve planejar apenas o que realmente afeta:

- prosa;
- corpus;
- exemplos;
- demonstrações;
- recursos;
- unidade de produção.

---

## A. Arquitetura da prosa

### 1. Qual é o regime predominante da prosa?

### 2. Como a exposição deverá começar?

### 3. Que insuficiência, problema ou relação precisa aparecer antes da definição?

### 4. Que conceitos podem ser definidos diretamente?

### 5. Quando a notação deve entrar?

### 6. Como prosa e fórmulas dividirão trabalho?

### 7. Onde a exposição deve desacelerar?

### 8. Onde pode ser econômica?

### 9. Que transições conceituais precisam ser explicitamente construídas?

### 10. Como as Partes se conectam sem reensino automático?

A estrutura pode assumir movimentos diferentes conforme a matemática.

Exemplos:

\[
\text{insuficiência}
\rightarrow
\text{necessidade}
\rightarrow
\text{conceito}
\rightarrow
\text{uso}
\]

\[
\text{afirmação}
\rightarrow
\text{interpretação}
\rightarrow
\text{justificação}
\]

\[
\text{operação}
\rightarrow
\text{padrão}
\rightarrow
\text{propriedade}
\rightarrow
\text{generalização}
\]

Nenhuma sequência é obrigatória.

---

## B. Corpus teórico

### 11. Quais fontes do corpus geral terão prioridade?

### 12. Para qual função cada uma será utilizada?

Distinguir, quando pertinente:

- precisão;
- terminologia;
- pedagogia;
- demonstração;
- exemplos;
- representação;
- controle de fronteira.

### 13. É necessária alguma fonte específica adicional?

### 14. Que partes das fontes não devem ser importadas?

Evitar:

- formalismo excessivo;
- conteúdo posterior;
- sequência inadequada;
- expansão lateral;
- exemplo com pré-requisito indevido.

O corpus sustenta a produção sem governar automaticamente a arquitetura.

---

## C. Exemplos

### 15. Que exemplos controlados possuem melhor ganho didático?

### 16. Que variável ou relação cada exemplo isola?

### 17. É útil manter algum exemplo persistente?

Somente quando cada retorno realizar trabalho novo.

### 18. Que não exemplos ou contraexemplos são necessários?

### 19. Que exemplos devem ser evitados por custo curricular?

Não estabelecer quota universal.

---

## D. Demonstrações

### 20. Que resultados merecem demonstração?

### 21. Qual demonstração possui função formativa?

### 22. O estudante precisa acompanhar prova completa ou apenas compreender a ideia?

### 23. Que resultados podem receber justificativa curta?

### 24. Que resultados podem ser deslocados para a prática?

### 25. Que método de demonstração está legitimamente disponível?

A demonstração deve ensinar matemática, não funcionar como ornamentação formal.

---

## E. Recursos teóricos

### 26. O que precisa tornar-se perceptível?

### 27. A prosa e os símbolos já realizam essa função?

Se sim, não criar recurso autônomo por hábito.

### 28. Que representação é adequada?

### 29. Qual fidelidade matemática é necessária?

### 30. O recurso é essencial ou complementar?

### 31. Qual é seu núcleo representacional?

Completar:

### 32. O que precisa obrigatoriamente aparecer?

### 33. O que pode ser omitido?

### 34. Que relação não pode ser sugerida incorretamente?

### 35. Como o recurso se integra à prosa?

### 36. Ele permanece legível na escala real da apostila?

Podem aparecer:

- diagramas;
- gráficos;
- retas;
- tabelas;
- árvores;
- construções geométricas;
- esquemas;
- ilustrações;
- imagens;
- composições híbridas.

SVG, HTML/CSS, raster ou outra tecnologia são decisões posteriores, salvo quando a própria fidelidade exigir antecipar restrições.

---

## F. Estratégia de produção teórica

### 37. O Bloco pode ser produzido integralmente?

### 38. A densidade exige produção Parte por Parte?

### 39. Alguma Parte exige excepcionalmente unidade menor?

### 40. A quantidade e a complexidade dos recursos justificam divisão?

### 41. Há risco de compressão se tudo for solicitado de uma vez?

Aplicar:

> **pedir apenas a quantidade de texto que pode receber o aprofundamento que merece.**

## Resultado esperado

Ao final, o Bloco deve estar pronto para orientar a produção teórica sem exigir nova decisão arquitetônica relevante durante a redação.

# IV. ESTRUTURA DO BLOCO — TEXTO PRÁTICO

## Função

Definir:

> **como a compreensão construída pelo Texto Teórico será convertida em ação matemática observável, flexível e progressivamente autônoma.**

Princípio superior:

> **A teoria determina o que o estudante pode compreender; a prática determina o que ele consegue fazer autonomamente com essa compreensão.**

Segundo princípio:

> **A arquitetura prática não deve espelhar mecanicamente a arquitetura teórica.**

O Texto Prático não é:

- continuação editorial da teoria;
- resumo seguido de exercícios;
- cópia da ordem das Partes;
- lista de questões anexada.

A prática pode:

- reorganizar conhecimentos;
- combinar Partes;
- integrar Blocos já construídos;
- inverter a ordem de mobilização;
- retirar apoios;
- promover escolha;
- exigir justificativa;
- promover transferência.

Desde que não introduza silenciosamente conhecimento novo.

A unidade de planejamento é:

\[
\boxed{\text{competência matemática em ação}}
\]

e não o exercício isolado.

---

## A. Contrato da prática

### 1. O que o Texto Teórico efetivamente construiu?

Levantar apenas o que realmente está disponível:

- conceitos;
- propriedades;
- procedimentos;
- representações;
- notações;
- justificativas;
- demonstrações;
- métodos.

### 2. Alguma ideia apareceu apenas superficialmente?

Se sim, ela ainda não pode sustentar cobrança exigente.

### 3. Qual é o contrato negativo?

O que ainda não pode ser cobrado?

Proteger contra:

- técnica posterior;
- fórmula não construída;
- atalho;
- notação não estabilizada;
- método demonstrativo indisponível;
- dificuldade auxiliar indevida.

Uma questão externa excelente pode precisar ser:

- adaptada;
- adiada;
- descartada.

### 4. Qual é o contrato de saída prático?

Definir em ações observáveis.

Podem aparecer:

- reconhecer;
- classificar;
- distinguir;
- representar;
- traduzir;
- calcular;
- manipular;
- transformar;
- comparar;
- escolher procedimento;
- justificar;
- demonstrar;
- interpretar;
- verificar;
- construir;
- diagnosticar erro;
- corrigir;
- integrar;
- transferir.

Evitar formulações vagas como apenas “compreender”.

---

## B. Competências matemáticas em ação

### 5. Quais competências são centrais?

### 6. Quais são auxiliares?

A prática deve impedir que uma habilidade instrumental domine a dificuldade-alvo.

### 7. Que evidência é suficiente para afirmar domínio?

Perguntar, conforme a competência:

- uma ocorrência basta?;
- precisa de repetição?;
- exige fluência?;
- precisa mudar de representação?;
- exige justificativa?;
- o estudante precisa escolher o método?;
- precisa transferir?

### 8. Alguma competência está super-representada ou ausente?

Quando útil, utilizar internamente uma matriz:

\[
\text{competência}\times\text{atividade}.
\]

Ela não precisa aparecer na apostila.

---

## C. Progressão da prática

### 9. O que muda qualitativamente ao longo da prática?

Não presumir:

\[
\text{fácil}\rightarrow\text{médio}\rightarrow\text{difícil}.
\]

A dificuldade pode crescer por:

- maior autonomia;
- menor apoio;
- mudança de representação;
- necessidade de escolher método;
- aumento das relações sob controle;
- exigência de justificar;
- integração;
- transferência.

A dificuldade deve crescer principalmente pelo **controle matemático exigido**, não pelo tamanho da conta.

### 10. Que apoios são legítimos no início?

Podem aparecer:

- estratégia sugerida;
- representação inicial;
- decomposição em etapas;
- tabela parcial;
- pergunta-guia.

### 11. Quando esses apoios devem desaparecer?

Quando pertinente, planejar:

\[
\text{apoio}
\rightarrow
\text{redução do apoio}
\rightarrow
\text{autonomia}.
\]

---

## D. Distribuição da prática

### 12. A prática será local, acumulada ou híbrida?

#### Prática local

Associada imediatamente a determinada Parte.

#### Prática acumulada

Realizada depois que várias Partes podem atuar juntas.

#### Prática híbrida

Combina treino local com integração posterior.

Não impor:

\[
\text{Parte teórica A}
\rightarrow
\text{Prática A}
\rightarrow
\text{Parte teórica B}
\rightarrow
\text{Prática B}.
\]

A distribuição deve seguir função pedagógica.

---

## E. Núcleo e módulos

O núcleo necessário do Texto Prático é:

\[
\boxed{
\text{Exercícios}
+
\text{Gabarito Comentado}
}
\]

Os seguintes elementos são **módulos condicionais**:

- Exemplos Resolvidos;
- Quiz;
- Erros Comuns ou Erros Críticos;
- Desafio;
- questões externas;
- recursos visuais específicos.

Nenhum deles deve existir por obrigação editorial.

---

## F. Exemplos Resolvidos

### 13. Existe salto real entre compreender a teoria e saber iniciar a resolução?

### 14. Que salto estratégico precisa ser modelado?

Pode envolver:

- organização de dados;
- escolha de representação;
- escolha de método;
- início de demonstração;
- verificação;
- estratégia.

### 15. Quantos exemplos são necessários?

O número deve corresponder aos **saltos estratégicos distintos**.

Pode ser zero.

Não estabelecer quota.

---

## G. Exercícios

### 16. Que tipos de ação precisam ser exercitados?

Selecionar apenas as necessárias:

- reconhecimento;
- execução;
- construção;
- tradução;
- escolha de método;
- justificação;
- demonstração;
- diagnóstico;
- integração;
- transferência.

### 17. Quantos exercícios são necessários?

A quantidade deve emergir de:

\[
\boxed{
\text{cobertura}
+
\text{variedade funcional}
+
\text{fluência necessária}
}
\]

Não fixar números universais.

### 18. Onde a repetição é deliberada?

Repetição pode ser legítima para:

- estabilização;
- automatização;
- fluência.

Ela não precisa ser disfarçada de variedade.

### 19. Cada exercício acrescenta algo?

Aplicar:

> **O que este exercício exige que os anteriores ainda não exigiram?**

Pode acrescentar:

- nova representação;
- menos apoio;
- inversão;
- escolha;
- justificativa;
- diagnóstico;
- integração;
- transferência.

Trocar apenas números não produz novidade funcional.

---

## H. Integração e transferência

### 20. Há necessidade de questões integradoras?

Integração significa competências realmente atuando em conjunto.

Questão longa não é automaticamente integradora.

### 21. Há necessidade de transferência?

Perguntar se o estudante reconhece a mesma estrutura quando muda:

- representação;
- aparência;
- contexto matemático;
- linguagem;
- organização dos dados.

Mera troca de cenário não constitui transferência.

---

## I. Quiz

### 22. O Quiz realiza função própria?

Pode ser útil para:

- reconhecimento rápido;
- distinções;
- leitura de notação;
- condições de aplicação;
- verdadeiro/falso;
- diagnóstico.

Se exige estratégia ou cálculo prolongado, provavelmente já deixou de ser Quiz.

### 23. Onde o Quiz deve aparecer?

A posição pode servir a:

- prontidão;
- estabilização;
- diagnóstico intermediário;
- fechamento rápido.

A posição deriva da função.

---

## J. Erros Comuns ou Erros Críticos

### 24. Existem erros suficientemente importantes para tratamento próprio?

Distinguir falha conceitual de deslize banal.

### 25. Como o erro deve ser tratado?

Pode ser:

- integrado a exercício;
- transformado em “encontre o erro”;
- explicado e corrigido;
- comparado a outras soluções;
- reunido em seção autônoma.

Uma seção específica só se justifica quando comparar padrões de erro produz ganho adicional.

---

## K. Desafio

### 26. Existe função real para um Desafio?

Só utilizar quando acrescentar:

- integração;
- transferência;
- investigação;
- autonomia superior.

Não criar porque “todo Bloco termina com Desafio”.

---

## L. Corpus prático

### 27. Que funções as fontes precisam cumprir?

Uma fonte pode fornecer:

- correção matemática;
- método de resolução;
- repertório de problemas;
- calibração vestibular;
- calibração olímpica;
- dados;
- contextos;
- representações;
- distratores.

### 28. Quais fontes são normativas e quais são inspiradoras?

Uma fonte rigorosa pode não ser boa para definir progressão pedagógica.

Uma prova real pode calibrar autonomia sem determinar o currículo.

### 29. Que fontes primárias devem ser priorizadas?

Para questões autênticas, preferir quando possível:

- caderno oficial;
- prova oficial;
- solução oficial;
- documento original.

Bancos secundários ajudam na localização, mas não substituem automaticamente a fonte primária.

---

## M. Proveniência das questões

Adotar a taxonomia:

\[
\boxed{
\text{Autêntica}
\quad
\text{Baseada/Adaptada}
\quad
\text{Original}
}
\]

### Questão Autêntica

Questão oficial preservada matematicamente, admitindo normalização editorial.

Usar quando se deseja:

- contato com linguagem real de banca;
- transferência;
- integração avaliativa;
- menor tutela;
- calibração realista.

Não possui superioridade automática.

### Questão Baseada/Adaptada

Utiliza elementos de uma questão anterior, como:

- ideia;
- estrutura;
- técnica;
- contexto;
- representação;
- raciocínio;
- distrator;

mas constitui um novo item.

Preferir quando a ideia é boa, mas a questão original contém:

- pré-requisito futuro;
- cálculo excessivo;
- dificuldade auxiliar;
- contexto inadequado;
- representação ruim;
- formulação incompatível.

Nunca apresentar como questão oficial.

### Questão Original

Criada especificamente para o contrato local.

Preferir quando é necessário controlar:

- pré-requisitos;
- apoio;
- dificuldade;
- representação;
- erro;
- variável;
- integração;
- progressão.

Não fixar porcentagens universais entre as três categorias.

### Registro de proveniência

Questões autênticas devem registrar, quando pertinente:

- banca;
- ano;
- fase ou dia;
- identificação.

Questões baseadas/adaptadas devem manter internamente a origem ou inspiração quando houver.

Questões originais devem ser tratadas como autorais do Plano.

Não realizar falsa atribuição.

Disponibilidade pública não significa automaticamente liberdade irrestrita de reprodução.

---

## N. Recursos visuais da prática

Aplicar:

\[
\boxed{
\text{FUNÇÃO MATEMÁTICA}
\rightarrow
\text{REPRESENTAÇÃO}
\rightarrow
\text{FIDELIDADE}
\rightarrow
\text{IMPLEMENTAÇÃO}
}
\]

### 30. Que ação o estudante realizará sobre o recurso?

Pode:

- observar;
- interpretar;
- extrair informação;
- completar;
- construir;
- comparar;
- transformar;
- corrigir.

Distinguir entre:

- recurso fornecido;
- recurso que o estudante deve produzir.

Fornecer uma representação não pode destruir justamente a competência avaliada.

### 31. Qual fidelidade matemática o recurso exige?

Perguntar se participam da solução:

- escala;
- posição;
- inclinação;
- coordenadas;
- proporções;
- medidas.

Distinguir figura esquemática de representação matematicamente informativa.

### 32. O recurso fornece pistas extramatemáticas?

Auditar:

- cor;
- alinhamento;
- proximidade;
- escala;
- agrupamento;
- desenho preciso demais.

### 33. Imagem gerada por IA é apropriada?

Regra forte:

> **Imagem gerada por IA pode ilustrar uma situação concreta, mas não deve funcionar como fonte de verdade métrica, geométrica, gráfica ou numérica.**

Ela não deve determinar dados cuja precisão seja necessária para a resolução.

---

## O. Gabarito Comentado

### 34. O gabarito corrige aquilo que a atividade tornou observável?

A profundidade deve ser proporcional.

Pode exigir:

- resposta curta;
- procedimento;
- estratégia;
- justificativa;
- demonstração;
- diagnóstico de erro.

O Gabarito Comentado não deve transformar-se em segunda aula teórica.

### 35. A questão admite mais de uma estratégia correta?

Se sim, distinguir:

- resposta-modelo;
- critério de suficiência.

O estudante não precisa reproduzir exatamente o caminho oficial.

### 36. Existem respostas alternativas, casos-limite ou interpretações legítimas?

Testar especialmente:

- questões abertas;
- demonstrações;
- modelagem;
- linguagem natural.

### 37. O gabarito está ensinando teoria indispensável nunca construída?

Se sim:

\[
\boxed{
\text{o exercício saiu do escopo}
\quad\text{ou}\quad
\text{a prática revelou lacuna real na teoria}
}
\]

---

## P. Auditoria adversarial

### 38. A atividade sobrevive a leitura adversarial?

Perguntar:

- existe outra resposta correta?;
- há contraexemplo?;
- alguma hipótese é insuficiente?;
- alguma condição de domínio foi esquecida?;
- há caso degenerado?;
- existe leitura alternativa legítima?;
- alguma alternativa é ambígua?;
- alguma pista visual entrega a resposta?;
- existe método trivial que contorna a competência-alvo?;
- a dificuldade observada é realmente a dificuldade pretendida?

---

## Q. Auditoria de cobertura

### 39. Todas as competências centrais aparecem?

### 40. Alguma está super-representada ou quase ausente?

### 41. Existe variedade funcional?

### 42. Há redundância?

### 43. A progressão retira apoio quando necessário?

### 44. Existe integração?

### 45. Existe transferência quando necessária?

### 46. Cada atividade cobra apenas conteúdo legitimamente disponível?

### 47. Alguma depende de pré-requisito oculto?

### 48. Os módulos opcionais possuem função real?

### 49. O gabarito possui profundidade proporcional?

### 50. A prática desenvolve autonomia ou apenas repetição?

---

## R. Unidade de produção prática

### 51. O Texto Prático do Bloco pode ser produzido integralmente?

### 52. É útil separar Exercícios e Gabarito?

### 53. Deve ser produzido Parte por Parte?

### 54. Alguma Parte exige produção isolada?

### 55. A quantidade de questões, recursos ou auditorias justifica divisão?

Não dividir automaticamente.

---

## Resultado esperado

Ao final, a prática do Bloco deve possuir:

- contrato claro;
- competências observáveis;
- progressão;
- distribuição;
- módulos necessários;
- corpus;
- proveniência;
- exercícios suficientemente variados;
- recursos matematicamente fiéis;
- gabarito proporcional;
- auditoria de cobertura;
- auditoria adversarial;
- unidade de produção adequada.

# V. ESTRUTURA DAS PARTES EM TÓPICOS SEM BLOCOS — NÚCLEO MATEMÁTICO COMUM

## Função

Quando o Tópico não justificar Blocos, organizar diretamente o conjunto de Partes como percurso matemático único.

A ausência de Blocos não elimina a separação entre Texto Teórico e Texto Prático.

O fluxo é:

\[
\boxed{
\text{Tópico}
\rightarrow
\text{Partes}
\rightarrow
\begin{cases}
\text{Texto Teórico}\\
\text{Texto Prático}
\end{cases}
}
\]

---

## A. Arquitetura geral das Partes

### 1. Por que o Tópico precisa ser dividido em Partes?

### 2. Qual é o menor número necessário?

### 3. Que parcela do movimento global cabe a cada Parte?

### 4. Qual é a função de cada Parte?

### 5. Por que aparecem nessa ordem?

### 6. Que dependências existem entre elas?

### 7. Que assimetrias são legítimas?

### 8. Alguma Parte está realizando trabalho demais?

### 9. Alguma Parte possui função insuficiente?

### 10. A decisão de não criar Blocos continua justificada?

Para cada Parte, resolver:

### 11. Qual é sua identidade?

### 12. Qual é sua pergunta central?

### 13. Qual é sua função dentro do Tópico?

### 14. Qual é seu contrato de entrada?

### 15. O que precisa ser retomado?

### 16. O que ainda não pode ser pressuposto?

### 17. Qual é seu contrato de saída?

### 18. Qual é seu conteúdo nuclear?

### 19. Qual é seu conteúdo auxiliar?

### 20. Quais são suas fronteiras?

### 21. Qual é seu movimento interno?

### 22. Quais são suas dependências?

### 23. Qual é o estatuto dos elementos matemáticos?

### 24. O que deve emergir por necessidade?

### 25. O que pode ser definido diretamente?

### 26. Onde estão os gargalos?

### 27. Quais pontos são simples?

### 28. Que confusões precisam ser resolvidas?

### 29. Que notação entra?

### 30. Como se conecta às demais Partes?

### 31. Onde deve parar?

---

## Resultado esperado

As Partes devem constituir um percurso único, sem necessidade artificial de Blocos, e estar prontas para receber separadamente a arquitetura teórica e a arquitetura prática.

# VI. ESTRUTURA DAS PARTES EM TÓPICOS SEM BLOCOS — TEXTO TEÓRICO

## Função

Aplicar às Partes, na escala adequada, os mesmos princípios de produção teórica usados nos Blocos.

Não criar uma metodologia paralela.

Para cada Parte, decidir somente o que for necessário sobre:

- regime da prosa;
- sequência explicativa;
- entrada da notação;
- corpus teórico;
- exemplos;
- contraexemplos;
- demonstrações;
- representações;
- fidelidade;
- integração entre prosa e recurso;
- unidade de produção.

Perguntas centrais:

1. Como a prosa desta Parte deve avançar?
2. Que fonte possui função especial aqui?
3. Que exemplos realmente ajudam?
4. Que demonstração é necessária?
5. O que precisa tornar-se perceptível?
6. Que recurso, se houver, realiza essa função?
7. Que fidelidade é exigida?
8. A Parte pode ser produzida integralmente?
9. Existe razão real para subdividi-la?

A ausência de Bloco não justifica menor controle arquitetônico, apenas elimina uma camada intermediária desnecessária.

---

# VII. ESTRUTURA DAS PARTES EM TÓPICOS SEM BLOCOS — TEXTO PRÁTICO

## Função

Aplicar às Partes, na escala adequada, a mesma **Camada do Texto Prático** utilizada nos Blocos.

Não duplicar literalmente dezenas de perguntas. Ajustar a escala.

O conjunto das Partes assume a função de coordenação global da prática.

Devem ser resolvidos, quando pertinentes:

- contrato de entrada prático;
- contrato negativo;
- contrato de saída;
- competências matemáticas em ação;
- evidências de domínio;
- progressão;
- apoios e retirada de apoio;
- prática local, acumulada ou híbrida;
- Exemplos Resolvidos;
- exercícios;
- repetição e fluência;
- integração;
- transferência;
- Quiz;
- Erros Comuns/Críticos;
- Desafio;
- corpus prático;
- questões Autênticas, Baseadas/Adaptadas e Originais;
- proveniência;
- recursos visuais;
- fidelidade;
- Gabarito Comentado;
- auditoria adversarial;
- cobertura;
- unidade de produção.

Perguntas centrais:

1. Que competências cada Parte torna praticáveis?
2. A prática deve acompanhar cada Parte ou integrar várias?
3. Que apoio é necessário?
4. Que módulos condicionais realmente possuem função?
5. Que corpus é adequado?
6. Como a dificuldade cresce?
7. Que transferência é necessária?
8. O gabarito corrige exatamente o que a atividade tornou observável?
9. Há teoria nova escondida?
10. A prática atingiu autonomia suficiente para encerrar?

# VIII. AUDITORIA, CONGELAMENTO E REABERTURA

## 1. Teste de dependência

Perguntar:

> **cada conceito, símbolo, operação, representação, demonstração e exercício aparece somente depois dos conhecimentos de que realmente depende?**

Se não, revisar.

---

## 2. Teste de compressão estrutural

Perguntar:

> **se retirarmos títulos, numeração, caixas e convenções editoriais, ainda conseguimos reconstruir a transformação matemática do começo ao fim?**

Se não, pode existir apenas um sumário, não uma arquitetura.

---

## 3. Teste de completude

Perguntar:

> **tudo o que precisa ser resolvido para cumprir o contrato de saída foi resolvido?**

Não perguntar:

> **tudo o que poderia ser dito sobre o assunto foi incluído?**

---

## 4. Teste de legitimidade

Perguntar:

> **todo símbolo, operação, representação, demonstração e capacidade exigida possui base legitimamente construída?**

Se não, localizar:

- pré-requisito oculto;
- antecipação;
- lacuna;
- excesso da prática;
- falha de fronteira.

---

## 5. Auditoria matemática

Verificar:

- erro;
- lacuna;
- dependência escondida;
- antecipação;
- fronteira inadequada;
- estatuto incorreto;
- formalismo excessivo.

---

## 6. Auditoria da prosa

Verificar:

- arquitetura adequada;
- excesso verbal;
- excesso simbólico;
- transições frágeis;
- exemplo ocupando função da explicação;
- demonstração interrompendo o movimento sem ganho.

---

## 7. Auditoria do corpus

Verificar:

- fontes suficientes;
- função de cada fonte;
- fonte governando indevidamente a arquitetura;
- corpus teórico e prático confundidos;
- dependência excessiva de fonte secundária quando a primária é necessária.

---

## 8. Auditoria representacional

Verificar:

- recurso possui função;
- representação adequada;
- fidelidade suficiente;
- recurso legível;
- pista indevida;
- implementação escolhida cedo demais;
- redundância com a prosa;
- imagem contextual tratada indevidamente como dado matemático.

---

## 9. Auditoria teórica

Verificar:

- compreensão suficientemente construída;
- exemplos funcionais;
- demonstrações proporcionais;
- notação legitimada;
- corpus adequado;
- unidade de produção coerente.

---

## 10. Auditoria prática

Verificar:

- competências observáveis;
- teoria nova não escondida;
- progressão real;
- retirada de apoio;
- cobertura;
- variedade funcional;
- autonomia;
- proveniência;
- fidelidade dos recursos;
- gabarito proporcional;
- validade adversarial.

---

# Congelamento

Uma arquitetura específica pode ser congelada quando estiver suficientemente resolvida em:

- identidade;
- pergunta;
- contratos;
- fronteiras;
- movimento;
- dependências;
- profundidade;
- estatutos;
- notação;
- regimes;
- organização interna;
- prosa, quando pertinente;
- corpus;
- recursos essenciais;
- estratégia de produção;
- capacidades da prática;
- critério de encerramento.

Congelamento significa:

> **encerrar refinamento opcional.**

---

# Reabertura

Não reabrir por:

- existir outra sequência possível;
- outra fonte organizar diferente;
- desejo de acrescentar metodologia;
- desejo de aumentar detalhamento;
- busca de simetria;
- preferência estética;
- existência de mais exercícios possíveis;
- mudança técnica de SVG, CSS, HTML ou rasterização.

Reabrir somente diante de problema real, como:

- erro matemático;
- lacuna;
- dependência ausente;
- fronteira impraticável;
- formalização inadequada;
- corpus insuficiente;
- representação essencial mal concebida;
- estratégia de produção inadequada;
- prática legítima revelando lacuna teórica;
- exercício ambíguo;
- falha adversarial estrutural;
- divisão em Blocos ou Partes que não se sustenta.

---

# Economia e não burocratização

Antes de considerar uma aplicação estrutural encerrada, perguntar:

- alguma pergunta foi respondida apenas por obrigação?;
- duas decisões poderiam ser fundidas?;
- alguma seção virou formulário?;
- algum detalhe pertence melhor às Regras Gerais?;
- a estrutura está ajudando a produzir ou apenas criando trabalho?;
- existe detalhamento técnico prematuro?;
- o planejamento continua ágil?;
- a teoria e a prática estão sendo duplicadas?;
- o nível de detalhe é proporcional ao problema?

Aplicar:

\[
\boxed{
\text{completude normativa}
\neq
\text{exaustividade metodológica}
}
\]

# Relação final entre teoria e prática

Preservar simultaneamente três princípios.

## 1. A teoria estabelece o espaço legítimo da prática

O Texto Prático não pode exigir:

- conceito não construído;
- símbolo não introduzido;
- operação não legitimada;
- representação não compreendida;
- método de demonstração indisponível.

## 2. A prática possui autonomia arquitetônica

Ela pode reorganizar o conhecimento para desenvolver:

- fluência;
- escolha;
- integração;
- autonomia;
- transferência.

## 3. A prática pode auditar a teoria

Quando uma atividade legítima exige uma distinção que nunca foi construída, existem duas hipóteses:

### A. A prática ultrapassou o contrato.

ou:

### B. A teoria possui uma lacuna real.

Somente a segunda hipótese justifica reabertura conceitual da teoria.

A prática não deve ser usada como justificativa para expansão arbitrária.

---

# Relação com o Prompt-Mestre

O Prompt-Mestre não constitui uma Estrutura Canônica.

Ele é um artefato derivado das decisões já auditadas.

O fluxo recomendado é:

\[
\boxed{
\text{Estruturas Canônicas}
\rightarrow
\text{Estruturação do Tópico}
\rightarrow
\text{Planejamento das unidades}
\rightarrow
\text{Congelamento}
\rightarrow
\text{Prompt-Mestre, quando útil}
\rightarrow
\text{Produção}
}
\]

Sua função é reduzir:

- esquecimento;
- deriva;
- antecipação;
- inconsistência;
- alucinação.

Não deve redesenhar silenciosamente a arquitetura.

As Estruturas Canônicas do Plano de Estudo Matemático devem preservar três movimentos fundamentais.

## Arquitetura matemática

\[
\boxed{
\text{DEPENDÊNCIA}
\rightarrow
\text{NECESSIDADE}
\rightarrow
\text{CONCEITO}
\rightarrow
\text{USO}
\rightarrow
\text{TRANSFERÊNCIA}
}
\]

## Representação

\[
\boxed{
\text{FUNÇÃO MATEMÁTICA}
\rightarrow
\text{REPRESENTAÇÃO}
\rightarrow
\text{FIDELIDADE}
\rightarrow
\text{IMPLEMENTAÇÃO}
}
\]

## Processo

\[
\boxed{
\text{ESTRUTURAR}
\rightarrow
\text{PRODUZIR NA UNIDADE ADEQUADA}
\rightarrow
\text{AUDITAR}
\rightarrow
\text{CONGELAR}
}
\]

O princípio final permanece:

> **As Estruturas Canônicas existem para melhorar as decisões que antecedem a produção, não para multiplicar etapas.**
